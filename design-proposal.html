「状态」— 用睡眠和 HRV 回答
今天该不该练

一款纯本地、只给自己用的 iOS App。数据来自 Apple Watch 同步进「健康」的睡眠分期、HRV 与静息心率， 用个人 30 天基线做对照，算出今天的准备度分数与训练建议。 不联网、不登录、不上传，全部数据留在手机里。

分数怎么算

核心原则：HRV 是个体基线数据，只有跟「你自己的过去」比才有意义 —— 所以每个指标都先转成相对基线的偏离量。

今日 61 分是怎么拼出来的
三个维度的具体算法
维度权重公式为什么这么算
HRV (SDNN) 40% z = ln(今日 ÷ 基线) ÷ ln(1.15)
分 = clamp(50 + 22z, 0, 100)		 HRV 呈右偏分布，取对数后「高于/低于基线」才对称
睡眠 35% 0.45×时长分 + 0.25×效率分
+ 0.30×分期分		 时长/效率对个人目标，分期（深睡+REM）与自己的基线比
静息心率 25% z = (基线 − 今日) ÷ (0.03×基线)
分 = clamp(50 + 18z, 0, 100)		 静息心率比基线低是好事；±3% 记为 1 个标准差
基线怎么建
  • · 滚动 30 天窗口（可调 14 / 30 / 60）
  • · 用中位数而非均值，抗离群值
  • · 同时保留 25–75 分位带，趋势图上画出来
  • · 有效样本 < 7 天时显示「基线建立中 n/7」
分档与建议
  • · 85+ 极佳 · 可以上强度
  • · 70–84 良好 · 正常训练
  • · 55–69 一般 · 降强度控量
  • · 40–54 欠佳 · 只做轻量活动
  • · <40 建议休息
归因句怎么生成（这个 App 真正值钱的地方）

不写「今日状态一般」这种废话，而是指出哪一项在拖后腿、拖了多少。

拖累型
「HRV 比基线低 8.7%，自主神经恢复还没跟上 —— 今天别冲重量。」
支撑型
「睡满 7h52m、深睡 1h06m，HRV 回到基线之上 —— 今天可以上强度。」
异常型
「今天数据缺失（昨晚没戴表）。基线只按 2 项算，参考度较低。」

数据是怎么流动的

小组件无法直接可靠地查 HealthKit，标准做法是 App 算完写入共享容器，小组件只读缓存。

刷新时机
  • ●App 每次进入前台 → 重新查询 + 重算 + reloadAllTimelines
  • ●小组件 timeline 每 30 分钟一条，兜底刷新
  • ●长按小组件 → 「刷新」按钮，直接触发重算（iOS 17+ 交互式小组件）

没有 Mac，怎么把 App 装到 iPhone 上

iOS App 必须由 macOS 编译签名。但「编译」和「用设备」可以拆开 —— 编译放在云端，装机放在你这台 Windows 上。

方案成本怎么走有效期 / 代价
A · 云端编译 + Sideloadly
推荐（先零成本跑通）		 ¥0 GitHub Actions 的 macOS runner（公开仓库免费不限量；私有仓库需绑定 $1 消费上限）编译出 .ipa → 下载到 Windows → Sideloadly 用你的 Apple ID 签名并安装到 iPhone 免费 Apple ID 证书 7 天到期；Sideloadly 可在 PC 开机且同 WiFi 时自动续签
B · 云端编译 + TestFlight
长期最省心		 $99/年 加入 Apple Developer Program → CI 里用 App Store Connect API 自动签名并上传 → iPhone 装「TestFlight」→ 收到即装，之后每次改代码只需 push 证书 1 年有效、自动更新、无 3 应用限制；需每年续费
C · 租一台云 Mac $85–165/月 MacStadium / MacinCloud / Scaleway 等租一台 Mac mini，远程桌面装 Xcode，直接编译 按月付费、不停机就在一直扣钱；国内访问海外节点延迟高
D · 买一台二手 Mac mini ¥1900–2800 闲鱼 / 转转上 M1 8+256 约 ¥1900–2800（2026 行情），本机装 Xcode 最省心 一次性成本，但从此不再受任何限制；验机要确认已退出 Apple ID、无企业监管锁
方案 A 的完整链路
  1. 推代码

    Windows 上写完 → git push 到 GitHub 仓库

  2. 云端自动编译

    Actions 在 macOS runner 上跑 xcodebuild，产出 .ipa 制品

  3. 下载 + 签名 + 装机

    Windows 装 Sideloadly（需官网版 iTunes + iCloud），拖入 .ipa，填 Apple ID，点 Start

  4. 开启开发者模式

    iOS 16+ 需在「设置 → 隐私与安全性 → 开发者模式」打开并重启一次

  5. 信任证书

    「设置 → 通用 → VPN 与设备管理」里信任你的 Apple ID

先说清楚三个坑
  • ① 证书 7 天到期。PC 关机或不在同一 WiFi，自动续签就失败，App 会打不开。所以方案 A 适合开发调试，长期用建议 B。
  • ② 免费账号同时只能签 3 个 App、每 7 天最多 10 个 App ID —— 你自己用完全够。
  • ③ 免费的 iCloud（网页版）用来处理双重验证。别装 Microsoft Store 版 iTunes，装 Apple 官网的网页版，否则认不出手机。
HealthKit 权限怎么办？
按 Apple 现行能力表，HealthKit 与 App Groups 对免费账号已开放。若实机签名时被拒，立刻切方案 B（$99）即可，不影响任何代码。

实施顺序

按「先能跑起来拿到分，再慢慢做好」的顺序，每一步都有可验证的产出。

M1
打通数据
能读到睡眠分期、HRV、静息心率并在界面上打印出来。拿到真实数值后再谈算法。
验收：界面显示昨晚真实 HRV
M2
基线 + 评分
30 天基线引擎、三维度加权、分档建议、归因句生成、数据缺失兜底。
验收：连续 7 天分数稳定
M3
小组件
App Group 共享、小尺寸 + 中尺寸、交互式刷新按钮、timeline 兜底。
验收：桌面能直接看到今日分
M4
趋势 + 洞察
周/月折线、睡眠与次日 HRV 散点、自动生成的规律结论、训练记录回写与关联。
验收：能回答「少睡 1 小时，第二天差多少」

决策 01
装机路径走哪条
A（零成本，每 7 天续签）／ B（$99/年，TestFlight 自动更新）／ 先 A 后 B
决策 02
视觉方向
A 暖中性（米白 + 墨绿/琥珀）／ B 纯深色 ／ C 无彩色
决策 03
评分偏保守还是偏激进
HRV 权重 40% 更看重恢复信号；调到 30% 则更看重睡眠。要不要加「敏感度」滑块让你自己调陡峭程度？
决策 04
训练记录要不要回写
今天页点「高/中/轻/休息」写进「健康」，趋势页就能对比「低分日硬练 vs 高分日训练」的效果。还是只读不写？
